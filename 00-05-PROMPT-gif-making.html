Master Prompt — Google Slides → Animated GIF

A reusable pre-prompt and field guide distilled from the “Popcorn Popping Axl Rose” Jesus-TV GIF project. Its purpose is to keep future GIF projects simple, visual, iterative, recoverable, and faithful to the actual Google Slides deck.

Why this page exists: Give ChatGPT the link to this page at the beginning of a future GIF project so it can recover the workflow before doing anything. This is not a prompt to immediately make a GIF. It is a prompt that teaches ChatGPT how we make GIFs together: inspect first, establish anchor frames, add only necessary transitions, visually verify, set timing last, and export only after approval.

THE CORE METHOD

MASTER WORKFLOW — GOOGLE SLIDES TO ANIMATED GIF 1. THE GOOGLE SLIDES DECK IS THE STORYBOARD. Treat each slide as a possible GIF frame. 2. VISUALLY INSPECT THE ACTUAL RENDERED SLIDES. Do not rely only on extracted text, object lists, speaker notes, accessibility text, templates, hidden/off-slide material, or old memory of the deck. What matters is what a viewer actually sees. 3. EXISTING SLIDES ARE ANCHOR FRAMES. Preserve good existing slides whenever possible. Do not rebuild the whole sequence. 4. ADD ONLY A HANDFUL OF TRANSITIONAL FRAMES. Usually 1–3 useful transitional slides between anchors is enough. Think children’s picture book coming alive, not 24-frame-per-second animation. 5. FAVOR SMALL CHANGES FROM FRAME TO FRAME. Whenever practical, duplicate an existing slide and change only one or two visual things. 6. LOCK STATIC ELEMENTS. Keep TV frame, camera position, crop, background, people, text placement, scale, and major objects pixel-consistent unless a deliberate change is part of the story. This prevents GIF jitter. 7. USE ACCUMULATION FOR GROWTH. If something grows or multiplies, keep what was already there and add to it: none → 1 → several → many. Do not randomly reposition earlier objects. 8. SYNCHRONIZE VISUAL ACTION WITH THE WORDS. Do not introduce a visual idea too early. If the lyric says “what once a sword, ploughshare came to be,” the sword should begin when that lyric begins—not during the preceding lyric. 9. ONE MAJOR VISUAL EVENT AT A TIME. A sequence is easier to understand when the viewer knows what changed. Examples from the successful project: SETUP → POP! → AXL REVEAL bare tree → first popcorn → more popcorn → popcorn-filled tree NOVEMBER RAIN → CHRIST NOW REIGN SWORD → PLOW 10. WORK ONE SECTION AT A TIME. Plan a short anchor-to-anchor sequence. Get approval. Then edit only that section. Visually inspect it. Then move to the next section. 11. DO NOT MAKE THE GIF EARLY. Finish and approve the storyboard first. Timing comes after the visual sequence is stable. 12. TIMING IS MUSICAL, NOT UNIFORM. Quick transformation frames move quickly. Lyric frames hold long enough to read. The final meaningful frame usually gets the longest hold. 13. THE CURRENT DECK IS AUTHORITATIVE. If I edit the Google Slides deck myself, re-render and re-inspect it. Do not restore old slides, cached frames, deleted transitions, or previous artwork merely because they existed in an earlier GIF. 14. EXPORT FROM CURRENT RENDERS. When approved, render every current slide at identical dimensions and build the GIF from those current renders. No interpolation, crossfade, invented frames, or per-frame cropping unless I explicitly ask. 15. VERIFY BEFORE DELIVERY. Check frame count, order, durations, total runtime, visual continuity, readability, looping, final hold, and that no stale frame replaced a newer slide.

OUR SUCCESSFUL ITERATIVE PATTERN

The earlier project worked because we did not try to solve the whole animation at once. These are the essential prompts/patterns worth reusing.

1. Initial storyboard inspection

Open my Google Slides deck [DECK NAME]. We are building individual frames for an eventual animated GIF, but DO NOT create the GIF yet. Base your analysis on what is actually visually displayed on each rendered slide. Ignore hidden, off-slide, speaker-note, template, accessibility, or other non-visible content unless I ask. Do not make changes yet. Study the deck as a sequence of GIF frames and give me a simple slide-by-slide plan that is smooth, visually interesting, easy to follow, consistent with the existing style, and SIMPLE enough that we do not get lost in the woods. Treat existing slides as ANCHOR FRAMES and recommend only a handful of transitional frames where they genuinely improve the animation. Favor small changes from frame to frame rather than constantly creating new scenes. STOP after proposing the sequence and wait for approval.

2. Plan one anchor-to-anchor section

Work ONLY on the sequence from [ANCHOR A] to [ANCHOR B]. Do not work beyond that section yet. First visually inspect the actual rendered anchor slides. Then propose the minimum useful frame sequence. Use this grammar unless the visuals suggest something better: ANCHOR → small change → payoff/change → NEXT ANCHOR. Prefer 1–3 transitional frames. Do not edit yet. STOP and wait for approval.

3. Edit an approved section

The proposed sequence is approved. Now edit ONLY this section. Create transitional frames by duplicating the appropriate existing slide(s) whenever possible. Keep static elements in exactly the same positions. Change only one or two visual things per transitional frame. After editing, visually inspect the resulting rendered sequence as consecutive GIF frames. Correct only obvious continuity problems. Do not create the GIF. STOP and tell me exactly what changed.

4. Re-time a visual idea when it arrives too early

The visual event is introduced too early. Synchronize it with the lyric/text that actually describes it. The preceding lyric/idea should finish completely before the new visual appears. From the moment the relevant lyric begins, keep the lyric visually locked while only the transformation imagery changes. Reuse the assets and positioning already created wherever practical. Do not redesign the artwork. Do not add unnecessary frames. After editing, visually inspect the corrected sequence and verify the visual no longer appears before its words.

5. Final storyboard review

The individual sections are approved. Do not edit yet. Render and visually inspect the entire deck from beginning to end as one animation storyboard. Check for accidental duplicates, obsolete transitional frames, jitter, objects appearing too early, objects disappearing too soon, confusing visual changes, and whether the final lyric/image feels like the true ending. Prefer using existing slides. Do not introduce another complicated visual event at the end. Recommend the exact ending sequence and which frame should receive the longest final hold. STOP for approval.

6. Timing pass

The storyboard is approved. DO NOT create the GIF yet. DO NOT edit the slides. Visually review every slide and assign a specific duration to each frame. Use timing categories as guidance, not mechanical rules: QUICK TRANSITION: roughly 0.25–0.5 sec NORMAL VISUAL BEAT: roughly 0.75–1.5 sec LYRIC / READING HOLD: roughly 1.5–5+ sec depending on text FINAL MEANINGFUL HOLD: usually the longest CLOSING BUTTON: enough to register without stealing the ending Give me: Slide | What happens | Recommended duration Calculate total runtime. STOP for approval before making the GIF.

7. GIF production pass

The storyboard and timing map are approved. NOW create the GIF. Do NOT modify Google Slides. Render the CURRENT ACTUAL APPEARANCE of every slide. Use identical dimensions for every frame. Use the exact approved frame durations. Do not: • add frames • remove frames • interpolate • crossfade • add transitions • alter artwork or text • crop individual slides differently • substitute cached old frames when current renders are available Loop continuously and give the final slide its complete approved hold before returning to Slide 1. Before delivery verify: • exact frame count • correct order • exact durations • correct total runtime • current deck renders were used • no stale/deleted frame returned • no artificial resizing/cropping/jitter • text remains readable • major visual transformations read clearly Correct production problems in the GIF/rendering, NOT in Google Slides. Then give me the finished GIF.

8. When I edit the deck myself

I have made edits to the Google Slides deck myself. The CURRENT DECK is now authoritative. Do not assume old numbering is still correct. Visually inspect the current rendered slides and remap the previous timing by visual correspondence. Do not blindly use old slide number + N. Identify new, deleted, duplicated, reordered, or substantially changed slides rather than guessing. Preserve previously approved durations wherever the corresponding frame can be confidently identified. Do not edit anything during this inspection pass. Report the new frame/slide/timing map first.

VISUAL GRAMMAR LEARNED FROM THE POPCORN / AXL PROJECT

  • SETUP → LOOK → POP! → REVEAL. A fast “POP!” frame works because it is brief and immediately followed by the payoff.
  • Accumulation: popcorn worked best as none → one → several → many, with earlier popcorn staying put.
  • Object transformation: the record transformation worked by keeping BEFORE and AFTER artwork at the exact same X/Y position, width, height, and rotation.
  • Transformation does not require a morph: sword → plow could be understood with a few discrete frames. Simplicity beat technical complexity.
  • Words control timing: the sword needed to arrive with “what once a sword…” rather than during “November Rain became redeemed.”
  • End by resolving, not escalating: after several visual jokes/payoffs, the final lyric should feel clean and conclusive rather than introducing another elaborate effect.
  • Long reading frames are okay. A frame can hold 4–7 seconds when the viewer genuinely needs that time to read it.
  • User edits override history. If the user changes Slides 1 and 2, those current slides become authoritative even if earlier versions were approved.

ANTI-WOODS RULES

KEEP US OUT OF THE WOODS. When uncertain, prefer: • fewer frames • duplicated slides instead of rebuilt scenes • one changing object instead of many • obvious visual storytelling instead of sophisticated effects • current rendered slides instead of assumptions • approval checkpoints instead of doing the whole project at once • direct BEFORE → AFTER transformations • readable holds instead of rushing lyrics • exact asset reuse instead of recreating approved artwork Do not “improve” things that have already been approved unless I ask. Do not solve a local problem by redesigning the whole deck. Do not generate a new picture when I tell you an existing supplied image is authoritative. Do not create the GIF while we are still designing frames.

REFERENCE CASE: “POPCORN POPPING AXL ROSE”

The finished working method emerged through repeated small approvals: opening setup and POP reveal; popcorn accumulation; original record → redeemed record; sword → plow synchronized to its lyric; final lyric and closing hold; timing pass; GIF export; then re-rendering whenever the deck was manually edited.

The important lesson is not the specific Axl/Jesus/popcorn imagery. The reusable lesson is the process: anchor frames + minimal transitions + visual inspection + continuity + approval checkpoints + timing last + current renders only.
